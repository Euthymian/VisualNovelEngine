------------- DIALOGUE SEGMENTATION --------------
Dialogue segmentation: A way to split a single line dialogue into multiple segments. The way we split is by {} with flags

{c} clear -> clear current segment then display new one        | -> wait for player input
{a} append -> append new segment to current one                |
{wc n} wait clear               | -> wait for time (n is amount of seconds)
{wa n} wait append              |

speaker "This is a very long dialogue {c} that will be split {a} into multiple segments." 

If DialogueBox is hidden, it will be shown automatically without call ShowDB() command if a characer starts speaking

------------- COMMAND HANDLING --------------
Command Parser will extract command from the dialohue line, find that command in command database then retrieve the command data to execute

A command looks like this: PlaySong("This is song name" -v 1 -p 1)
-> args are separated by space, space which inside "" will be ignored

There is a case where we only want to execute the following command after the previous one is done
-> John "Move left then right" [wait]MoveCharDemo(left), MoveCharDemo(right)
[wait] keyword is added to the first command means wait the first command to finish before execute the second

or [waitline]KyoyaAkase.SetSprite(-l 0 -spt p2 -spd 0.01), KyoyaAkase.SetSprite(-l 1 -spt p2e7 -spd 1)
[waitline] keyword is added means wait for every command in the line to finish before executing the next line. following [wait] in line will be ignored

Currently, for commmands which dont have [wait] ot [waitline] keyword and are subCommand (character subcommands), they arent be managed properly
for example: raelin.setcolor(red -spd 0.001) will set raelin color to red at extremely slow speed, then we call another color related command such as 
			[wait]raelin.setcolor(white) this is [wait] command which will be forced completed if we prompt. the new command should override the previous one,
			but it doesnt. when we prompt, the current [wait*] command will be removed from the list and trigger onTerminate() event (which run force complete).
			then, eventually, if we need to prompt to move to next dialogue line, we will call terminateAll() method, all commands in the list will be removed and 
			trigger onTerminate() event. now, the raelin.setcolor(red -spd 0.001) will trigger onTerminate() event and force complete the color change to red.

			To trigger this, try TestDialogueFiles with testCharacterCommands.txt file and spam click to force complete

			-> Can avoid this problem by call terminateAll() or wait for a safe period of time before executing the next related command 
			(while that period, not related command will be handled normally)

			-> by seperate needWait and non needWait commands, we can avoid this problem (CoroutineWrapper.needWait). this is done by triggering onTerminate() event
			only with needWait commands

		
WHEN FINALIZING CHARACTER COMMANDS, MAKE SURE NEW COMMAND WILL OVERRIDE THE PREVIOUS SAME TYPE COMMAND
THIS CAN BE DONE BY STOP CURRENT COROUTINE AND START A NEW ONE (LIKE WHAT WE HAVE DONE WITH COLOR)



------------------- LOGICAL LINE --------------
Logical line may look the same as dialogue line, but it offers functionality as a function call

Types:
	- INPUT LINE 
		Format: input "<Title>" 
		-> reveal input box and wait for player input

	- CHOICE LINE
		Format: 
			choice "<Question>"
			  {
					-Choice1
						line1
						line2
						line3
						choice "Sub Choice"
						{
							-SubChoice1
								line1
								line2
							-SubChoice2
								line1
								line2
						}
					-Choice2
						line1
						line2
			  }
		-> This is format of choice line. When player selects a choice, instead of continuing the main dialogue, new dialogue will be push to the queue (line1 line2 line3) 
		and once all lines are done, the main dialogue will continue

		-> The system allows nested choices, so you can have a choice inside a choice.




------------- VARIABLES --------------
We can define variables in the dialogue file, then use them in logical line such as $money = 100

There are 2 types of variable: Internal and External
	- Internal variable: Defined in the dialogue file, stored in VariableStore and only used in the dialogue file
	- External variable: Reference to actual variable in the game
		-> By doing this, we can change variable value within dialogue file and it will be reflected in the game

VariableStore is container of variable databases. Variables share same kind of data belong to a database. Default database will store variables which not explicitly assigned to a database
Example: 
	Int.characterCount: Int = database; characterCount = variable name
	String.characterName: String = database; characterName = variable name
	wow: Default database; wow = variable name

Anytime the game is loaded, every links of external variables will be reloaded because lambda is temporary and will be lost when the game is closed.

------------- LIVE2D CHARACTER SETUP --------------
Current setup:
- Becuase we are working with multiple character types (Sprite, Live2D) in the same scene (best practice is having only 1 type) and
  Live2D character is a complex one, so handling Live2D requires some extra steps
  - Create brand new Canvas and Camera to render Live2D character 
  - Change canvas type to Camera and assign the new cam
  - Both cameras (main camera and Live2D camera) and canvases should have the same setting (ortographic for cam and distance from cam for canvas) 
  - Create new Layer "UI - Live2D" and assign it to the new canvas
  - Limit culling mask of new camera to only render the "UI - Live2D" layer
  - Assign new layer to Live2D character prefab (Sample prefab)
  - Inside prefab, on CubismRenderController -> Sorting section, set Order in Layer to 1 and Mode to "Back To Front Order" -> This will 
	make Unity render all parts of Live2D char in the order of its parts
  - Create a new CustomRenderTexture to render Live2D character
  - Output of the new camera is assigned to the new CustomRenderTexture
  - In the main render group, inside Characters panel, create a new RawImage and assign the CustomRenderTexture to it
